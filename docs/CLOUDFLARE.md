# Публикация DataMaster в Cloudflare Pages

DataMaster размещается как статическое приложение в корне домена. Бесплатного тарифа Pages достаточно для демонстрации. Аккаунт Cloudflare нужен владельцу для публикации. Посетители открывают приложение без регистрации.

## Загрузка готовой сборки

1. Скачайте [DataMaster-Cloudflare-Pages.zip](https://raw.githubusercontent.com/NikitaCreatorDeveloper/datamaster/downloads-v1.0.0/DataMaster-Cloudflare-Pages.zip). В корне архива находятся index.html, каталог assets, иконка и файл заголовков _headers.
2. В панели Cloudflare откройте **Workers & Pages**, создайте приложение **Pages** и выберите **Direct Upload / Upload assets**. Загрузите ZIP или извлеките его и перетащите каталог со сборкой.
3. Выберите свободное имя проекта и нажмите **Deploy**. После завершения откройте выданный Cloudflare адрес на pages.dev.

## Автосборка из GitHub

При создании **Pages** выберите подключение Git-репозитория и предоставьте Cloudflare доступ к NikitaCreatorDeveloper/datamaster. Настройте сборку по таблице.

| Параметр | Значение |
|---|---|
| Рабочая ветка | main |
| Корневой каталог | Корень репозитория |
| Команда сборки | npm run build |
| Каталог результата | dist |
| Версия Node.js | 22.16.0, указана в .node-version. Можно явно задать NODE_VERSION=22.16.0. |
| Переменные приложения и секреты | Не требуются |

Сохраните настройки и запустите первую сборку. Следующие отправки в main запустят публикацию через Git-интеграцию Pages.

## Сборка своего архива

```sh
npm ci
npm test
npm run package:pages
```

Готовый файл появится в `release/DataMaster-Cloudflare-Pages.zip`. Эта команда выполняет проверку типов и собирает приложение. ZIP содержит только статические ресурсы сайта.

## Проверка после публикации

- Откройте выданный HTTPS-адрес на компьютере и смартфоне. Проверьте меню, смену языка и темы.
- Запустите «Очистка клиентской базы». В редакторе должны открыться 140 строк. Скачайте результат в XLSX и импортируйте скачанный файл.
- Если нужен корпоративный API, добавьте точный origin опубликованного сайта в разрешённые CORS origins этого API. Для Bearer-токена разрешите заголовок Authorization. Источник с авторизацией должен отвечать на preflight OPTIONS.
- Файл `public/_headers` попадает в корень dist. Pages применяет его для CSP, политики Referrer и заголовков безопасности. Содержимое таблиц остаётся в браузере посетителя.
